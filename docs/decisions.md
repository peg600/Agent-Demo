## DEC-008 会话与历史消息分阶段实施

- 日期：2026-11-27。状态：已确认。关联 TASK-007 r1。
- 确认依据：用户要求先提交并推送已有修改，再按设计实现客服会话和历史消息前后端，按模块提交，外部服务联调仍暂缓。此前提交已推送至 origin/main 的 1ed21fa。
- 沿用已设计的服务端匿名访客、HttpOnly cookie、归属校验和 PostgreSQL 持久化。以下是该授权范围内的实现细节：随机令牌的 HMAC 摘要入库，身份固定有效期30天；写接口校验 WEB_ORIGIN；会话创建及消息保存均通过客户端请求 ID 幂等处理；历史使用会话内递增序号分页。
- 本阶段仅保存用户消息，返回201（新建）或200（重试）和 processing=not_configured；原202/runId属于工作流阶段，不在尚未实现工作流时伪造运行或助手答复。新增客户端请求 ID 是保证重试一致性的接口细化。
- 匿名身份过期或清除cookie后，必须显式重新建立身份，旧身份历史不能自动找回；不新增账号登录、生产鉴权或身份迁移。
- 验证使用静态检查与无外部依赖的注入测试；不连接真实数据库、模型、RAGFlow或Langfuse。本轮后续新增提交先本地保存。
